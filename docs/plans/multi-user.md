# Авторизация и несколько пользователей

Согласовано 22 октября 2026 года: локальная регистрация по имени пользователя и паролю. F19, A44–A48 дополняют веб-MVP; поставка остаётся через Docker Compose.

1. Ввести учётные записи и серверные сессии: уникальное имя без учёта регистра, scrypt, ограничение попыток, cookie HttpOnly/SameSite, выход и срок действия. Публичны только вход, регистрация, состояние сессии и health.
2. Изолировать все существующие учебные сценарии каталогом пользователя: SQLite, настройки и credentials AI. Выбор каталога выполняет сервер по сессии. MCP получает отдельный внутренний credential и проверяет владельца до вызова инструмента. Фоновые задачи сохраняют контекст владельца.
3. Перенести существующий профиль с явным подтверждением при первой регистрации, используя резервную копию SQLite. Сохранить исходные файлы для восстановления. Остальные пользователи начинают с собственного профиля и примера.
4. Добавить страницу входа/регистрации, отображение имени, выход и смену пароля. При смене сессии очищать интерфейс и синхронизировать вкладки; старые запросы не должны применяться к новому пользователю.
5. Проверить регистрацию, ошибки и ограничения, восстановление сессии, отзыв при выходе/смене пароля, перенос и перезапуск; проверить чужие ID, независимые настройки и сброс, параллельные API/MCP-запросы. Выполнить существующие проверки backend, frontend и браузерный сценарий двух пользователей.

Общих материалов, администраторской панели и восстановления пароля через email в этом этапе нет. Владелец компьютера имеет доступ к локальным файлам; перенос прежнего профиля выполняется им при первом запуске. Подключения OAuth разных пользователей выполняются последовательно из-за одного callback-порта; уже подключённые пользователи могут работать одновременно.

Пароли и cookie следуют рекомендациям [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) и [Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Secure применяется при HTTPS; текущая HTTP-поставка ограничена loopback.

Реализовано 22 октября 2026 года. Решение описано в [ADR 0005](../adr/0005-multiple-local-users.md), результаты автоматической и браузерной проверки — в [протоколе приёмки](../acceptance/multi-user-2026-10-22.json). Основная локальная установка открывает регистрацию с явным переносом прежних данных; перенос рабочего профиля ожидает первой регистрации владельца.
